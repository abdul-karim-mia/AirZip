Extraction

Unpacking that guesses right

Smart folder handling

Archives are packed inconsistently. Some contain a single tidy root folder; others dump forty loose files at the top level. Most extractors treat both the same and let you deal with the mess.

AirZip looks first. One root item, a folder or a lone file, and it extracts beside the archive, because the archive already did the organising. Several root items and it creates a folder named after the archive to hold them.

The result: you never get a "Downloads folder explosion", and you never get Project_Backup/Project_Backup/Project_Backup/ either.

Split archives, joined transparently

Large downloads often arrive as numbered volumes: backup.7z.001, backup.7z.002, and so on. Some tools make you join them manually first; others only work if you happen to double-click the right one.

Point AirZip at any part and it locates the rest, then presents them to the 7-Zip engine through a single spanning stream, as if the archive had never been split. Progress and byte counts reflect the whole set, not one volume.

What you have
backup.7z.001   700 MB
backup.7z.002   700 MB
backup.7z.003   214 MB

→ double-click any one of them
→ AirZip extracts all 1.6 GB as one archive

Encrypted archives

When an archive is password-protected, AirZip shows a themed prompt instead of failing with an error code. Enter the password and extraction continues normally.

The prompt follows your light or dark theme like the rest of the app, and it appears only for the archives that actually need it.

Long paths and odd names

AirZip is long-path aware, so archives containing paths beyond the traditional 260-character limit extract without truncation or mysterious failures.

It's also UTF-8 code page aware, which means filenames in Japanese, Arabic, Cyrillic, emoji, whatever the archive contains, come out with their names intact rather than as mojibake.

Interface

The best UI is the one you don't see

AirZip's entire interface is a small progress card. Here it is, in both themes.

400 ms of patience

The progress window doesn't appear immediately. AirZip waits 400 milliseconds first, long enough that small archives finish silently and never flash a window at you. Only work that's actually going to take a moment gets a window.

Live theme switching

AirZip reads your Windows light/dark preference at launch and keeps listening. Change your theme while an extraction is running and the window redraws in the new palette immediately: no restart, no half-dark window.

Your accent, your sound

The progress bar colour is read from your DWM accent setting, so it matches the rest of your desktop. When extraction completes it plays SystemAsterisk, which means if you've silenced that in your Sound scheme, AirZip stays quiet too.

Sharp on any display

Per-monitor DPI aware. Drag the window between a 4K laptop screen and a 1080p external monitor and the text re-renders crisply on each, rather than scaling up into a blur.

Progress that means something

Current filename, percentage, and bytes done against the total, updated as it goes. Enough to know whether to wait or go make tea, and nothing beyond that.

Scriptable from the shell

Every action has a command-line flag and a meaningful exit code, so AirZip drops into batch files and deployment scripts as easily as it sits in Explorer. See the CLI reference →

Security

Archives are untrusted input

An archive is a file someone else made. It can name its entries anything at all, including paths that climb out of the folder you chose and land somewhere important. That attack has a name, zip slip, and it has hit a long list of otherwise-careful software.

AirZip validates every entry path before writing anything. Absolute paths are rejected. Any path containing a .. traversal is rejected. Extraction cannot escape the destination folder you chose, whatever the archive claims its contents are called.

Rejected before any write
// absolute path
C:\Windows\System32\evil.dll

// traversal out of the destination
..\..\..\Users\you\Startup\evil.exe

// mixed separators, same trick
docs/../../../autorun.inf
  • Runs as you, not as admin. The manifest requests asInvoker, so extraction never silently elevates. Only installing file associations asks for elevation, because it writes to HKLM.
  • No network surface. There is no socket code in the binary, so there is no remote attack surface to speak of.
  • Auditable in one sitting. The whole program is a single C++ source file you can read yourself.
Technical design

Why it's 2.1 MB

AirZip is written directly against the Win32 API: no framework, no UI toolkit, no managed runtime between the code and the operating system. Everything it needs is compiled into one executable, which is what keeps it this small and this quick to start.

Privacy

The shortest privacy policy you'll read

Everything below is about the app, the thing that runs on your machine.

  • No data collection. No personal data, no usage data, no telemetry, no crash reporting.
  • No internet connection. AirZip never connects to anything. It contains no networking code.
  • No accounts, ads, or upsells. There is no paid version to be nagged toward.
  • Minimal permissions. Only runFullTrust to run as a desktop app. No camera, microphone, location, or contacts access.
  • Only the files you point at. It reads the archive you opened and writes the extracted files. Nothing else on disk is touched.
This website uses Vercel Web Analytics to count page views and Speed Insights to measure how quickly pages load. Both are cookieless, store no personal data, and do not follow you across other sites. That's everything on here that measures anything.
Fits your workflow

However you like to open things

AirZip meets you where you already are, and coexists happily with every other tool on your machine.

Straight from Explorer

Double-click an archive once AirZip is your default handler, or right-click → Open with any time you want it just for one file. Both work from the moment it's installed.

Or straight from a script

Every action has a command-line flag and a meaningful exit code, so AirZip drops into batch files, deployment scripts and scheduled tasks. See the CLI reference →

Portable when you need it

The standalone build is one file. Keep it on a USB stick or a network share and run it on any machine. Nothing is written to the registry unless you ask for it.

Your existing tools keep working

AirZip only becomes the default handler if you choose it. Your previous handler for each file type is saved and restored on uninstall, so nothing is lost either way.
