Installation

Getting AirZip running

Two routes in, both free, both the same app. Pick the Store if you want it managed for you; pick the .exe if you want it portable.

Option 1 — recommended

Install from the Microsoft Store

The easiest route. Windows handles installation, updates, and removal, and the package is signed and scanned by Microsoft before it reaches you.

  • Updates arrive automatically — nothing to check or download again.
  • No admin rights required — installs under your user account.
  • Clean removal through Settings → Apps, with no registry leftovers.
  • Signed and verified by Microsoft's Store certification.
Open in Microsoft Store
1

Open the listing

Click the button, or search AirZip in the Store app.

2

Hit Get

It's a 2.1 MB download — it finishes about as fast as you can read this.

3

Right-click an archive

Choose Open with → AirZip. To make it permanent, see setting defaults.

Option 2 — portable

Download the standalone .exe

One file. Put it anywhere — a USB stick, a network share, a tools folder — and run it. Nothing is installed unless you explicitly ask for it.

  • Truly portable — runs from removable media with no installation.
  • Works offline and on machines where the Store is blocked by policy.
  • Full CLI control over installation and file associations.
  • Updates are manual — you decide when to replace the file.

File associations

Making AirZip the default

AirZip never takes over your file types silently. It only becomes the default handler if you run --install or set it yourself in Windows Settings.

Via the command line (.exe only)

Registers all 12 extensions at once and adds an entry to Add/Remove Programs. Prompts for elevation, because it writes to HKEY_LOCAL_MACHINE.

Elevated
> AirZip.exe --install

Via Windows Settings (either version)

Works for the Store build too, and lets you pick individual extensions rather than all twelve.

Settings path
Settings → Apps → Default apps
  → search "AirZip"
  → choose which extensions it handles

Extensions registered by --install

.zip.rar.7z .tar.gz.bz2 .xz.iso.cab .lzma.wim.arj
Your old handlers are kept safe. Before AirZip claims an extension, the existing handler is backed up to HKLM\SOFTWARE\AirZip\Associations. On uninstall they're restored from that backup — and if the backup is somehow missing, AirZip falls back to restoring a classic ProgID from OpenWithProgids (for example CompressedFolder for .zip).

Reading the exit code

AirZip is a GUI-subsystem binary, so cmd.exe does not wait for it by default — it returns immediately and you'd read the wrong code. Force the wait explicitly:

cmd.exe
> start /wait AirZip.exe archive.zip
> echo %ERRORLEVEL%
PowerShell
> $p = Start-Process AirZip.exe -ArgumentList 'archive.zip' -Wait -PassThru
> $p.ExitCode
Removal

Uninstalling

Leaving should be as easy as arriving.

Store version

Settings → Apps → Installed apps → AirZip → Uninstall. Or right-click it in the Start menu. Windows removes everything.

Installed .exe

Use Add/Remove Programs, or run the uninstall flag directly.

Elevated
> AirZip.exe --uninstall

Portable copy

Never ran --install? Then nothing was ever written to the registry. Delete the .exe and you're done. You can also remove %TEMP%\AirZip, though Windows will clear it eventually anyway.

Uninstall returns immediately. When AirZip is installed in Program Files, a running executable can't delete itself — so the work is handed to a temporary clone and the original process exits straight away. Removal completes a moment later in the background.
Three extensions may need reassigning. If the only handler available to restore for .arj, .lzma or .wim was an AppX package identity, Windows won't accept it as a plain file-type default and those extensions can end up unassociated. Reassign them in Settings → Default apps if you use them.
For developers

Build it from source

The most trustworthy install is the one you compiled yourself. It takes one command.

Requirements

  • Visual Studio 2022 Build Tools, Community, Professional or Enterprise
  • The C++ workload installed in the VS installer
  • The Windows SDK
  • 7z.dll and icon.ico present at the repository root — the resource compiler embeds both into the exe
build.cmd must keep CRLF line endings. With LF-only endings cmd.exe can't resolve the :probe label and fails with "The system cannot find the batch label specified". Watch your git autocrlf settings.
Clone and build 
> git clone https://github.com/abdul-karim-mia/AirZip
> cd AirZip\native
> build.cmd

Troubleshooting

When something goes sideways

Windows says "Windows protected your PC"

That's SmartScreen reacting to an executable it hasn't seen many times before. The standalone build isn't signed with an EV certificate, so new releases start without reputation.

Click More info, then Run anyway. If you'd rather not, the Store version is signed and verified by Microsoft, and building from source gives you a binary you produced yourself.

Double-clicking an archive still opens my old app

AirZip doesn't seize file types on its own. Either run AirZip.exe --install, or set it per-extension in Settings → Apps → Default apps.

Windows also sometimes pins a user choice that overrides system registration. If --install ran cleanly but nothing changed, set the extension manually once in Settings and it will stick.

"Not elevated" — exit code 4

--silent-install and --silent-uninstall deliberately never show a UAC prompt, because they exist for scripts. They need an already-elevated shell. Open an Administrator terminal and run them there, or use the non-silent --install, which prompts for you.

Extraction fails on a .rar / .iso / .wim file

Those formats are wired to the 7-Zip engine but aren't covered by our own test archives yet, so they're the most likely place for a bug to be hiding.

Please open an issue with the format and, if you can share it, a small sample. Samples become regression tests.

A folder appeared in %TEMP%\AirZip — is that normal?

Yes. The 7-Zip engine is embedded inside the executable so the download stays a single file; on first run it's unpacked to %TEMP%\AirZip and loaded from there. Deleting it is harmless — it's recreated next time.

My script gets the wrong exit code

AirZip is a GUI-subsystem binary, so cmd.exe doesn't wait for it. Use start /wait AirZip.exe … in cmd, or Start-Process -Wait -PassThru in PowerShell. See the CLI section for full examples.

Still stuck? Open an issue on GitHub with your Windows version, how you installed AirZip, and what the archive was. That's usually enough to reproduce it.
